# 制作ガイド

コマンド例のカレントディレクトリは `office-cast` です。

## 人間の準備とAIの制作

初回の環境準備・Azure Speechリソースの指定・アクセス権・ログインは、
[READMEの人間パート](../README.md#人間パート初回の準備)を参照してください。
人間がテーマ・対象者・尺・要点を伝え、AIが本ガイドと素材APIに従って台本・演出・ビルドを進めます。
内容の正確さ、音声の読み、音楽的な自然さ、公開範囲の最終判断は人間が行います。

Windowsでは `tools\setup.ps1`、macOS／Linux向けの入口は `sh tools/setup.sh` です。
以下のPowerShell例をPOSIX環境で実行するときは、Pythonを `.venv/bin/python`、
パス区切りを `/` に読み替えます。venvは環境ごとに作成し、OS間で共有しません。
共通版1.4.1ではレンダーとブラウザテストもOS別のvenvパスを使用します。
ブラウザは別途インストールし、標準のEdge以外は `OFFICE_CAST_BROWSER=chrome` 等で指定します。
macOS／Linuxの全工程は未検証で、Windows＋Edgeが制作確認済みの環境です。

## 制作環境と依存版

共通版1.4.2の対象環境は、通常版の **Python 3.14.8以降の3.14系** と
**Node.js 24.21.0以降の24 LTS系** です。プレビュー版や別のメジャー／マイナー系列は対象外です。
Python 3.13やNode 22が上流のサポート対象であることと、この版で確認する制作環境は区別します。

PC側ではPython・Node・Edgeをインストールし、使う実行ファイルとPATHを確認してください。
ランタイムの更新は他のプロジェクトにも影響します。既存Pythonを削除する必要はありません。
リポジトリのセットアップは、ランタイムを検査してから専用venv・Node依存・FFmpegを導入します。
OSのランタイムやPATH、npmレジストリの設定、Azureへのログインは変更しません。

WindowsではPythonランチャーの `py -3.14` を使います。ランチャーを使わない場合:

```powershell
.\tools\setup.ps1 -Python "C:\Path\To\Python314\python.exe"
```

macOS／Linuxでは `python3.14` を使います。別の実行ファイルを指定する場合:

```sh
sh tools/setup.sh /path/to/python3.14
```

既存venvがある場合はそのPythonを検査し、指定した実行ファイルで上書きしません。
不適合なvenvは、必要な依存情報と音声キャッシュを保存してからリポジトリ外に退避し、再セットアップします。
別OSのvenvや不完全なvenvも自動で修復・削除しません。

Python依存は `requirements.txt`、Node依存は `package.json` と `package-lock.json` で固定します。
1.4.2ではPlaywright Coreを1.63.0に更新し、NumPy 2.5.3・SciPy 1.18.1・
imageio-ffmpeg 0.6.0・GSAP 3.13.0は維持します。
Pillowはセキュリティ修正として12.3.0から13.0.0へ更新しています。
GHSA-8g5g-8vmr-9782（JPEGデコード時のヒープバッファオーバーフロー）と
GHSA-5xm2-6676-qcp9の修正版を採用し、共通API・素材・作品の `sharedVersion` は変更しません。
既存環境にも、セットアップを再実行して固定依存版を適用してください。
Playwrightはブラウザの更新に合わせて確認する依存です。`latest` がalpha版を指す取得元もあるため、
安定版を番号指定します。Playwright 1.64.0とNumPy 2.5.4は公式公開済みですが、

## 基本的な制作方針

Office Castは、教育番組のように、子どもから大人まで親しめる
落ち着いた説明映像を基本とします。
わかりやすさ、観察する楽しさ、動きによる発見を大切にします。

- **説明が主役**
  キャラクターや演出は、内容をわかりやすく伝えるために使います。
  派手さや笑いを優先して、伝えたい要点を埋もれさせません。

- **ナレーションは淡々と、自然に**
  過度にあおらず、落ち着いた口調で、短い文と適度な間を使います。
  淡々としていても機械的にはせず、聞き取りやすさを優先します。
  幼児向けの口調に寄せすぎず、専門用語は具体例や短い説明で補います。

- **構成は、一つずつ見せて伝える**
  一つの場面で伝える要点を絞り、問いや観察、具体例や実演、
  要点の整理を、作品の内容と尺に合わせて組み立てます。
  情報を一度に詰め込まず、見て理解できる時間を確保します。

- **何をしたか、どう変わったかを動きで見せる**
  ナレーションやテロップだけで説明せず、キャラクターの動作や
  小物の移動・組み立て・比較などで、行動と結果を見せます。
  「誰が、何をして、どう変わったか」が画面から伝わる演出にします。

- **親しみやすさは、小さな反応と「間」でつくる**
  視線、うなずき、戸惑い、無言の反応などを使い、
  説明を邪魔しない範囲で、楽しさや軽いユーモアを添えます。
  全員を常に動かしたり、すべての場面にギャグを入れたりしません。

- **音楽は、説明を支える**
  軽快で控えめなオリジナルBGMを基本とします。
  木琴・マリンバ・ピチカートなどの素朴な音色、
  規則的なリズム、適度な反復と小さな変化を活かします。
  ナレーションの聞き取りや、考えるための「間」を妨げません。

### 標準の作品構成：タイトル → 本編 → エンディング

ユーザーから別の指定がなければ、冒頭に独立したタイトルシーン、末尾に独立したエンディングを入れます。
本編の見出しや要点整理だけで代用せず、入口と締めが分かる構成にしてください。
タイトルは作品名とテーマを短く見せ、エンディングは要点や締めの言葉を見せて、最後の絵を読める間を残します。
短編ではタイトル2～3秒、エンディング3～4秒が目安です。固定尺ではなく、読みやすさと本編の説明時間に合わせます。
どちらもユーザーが指定した動画全体の尺に含め、例えば「30秒～1分」なら本編との合計をその範囲に収めます。

「タイトルなし」「エンディングなし」、別の構成・内容・長さなどの明示的な指定は、この標準より優先します。
片方だけ指定された場合は、指定されていないもう片方の標準を維持します。
SHU Worksロゴは任意です。エンディングを入れることと、ブランドロゴを使うことは別の判断です。
BGMは本編から継続し、通常のシーン境界では全体をフェードせず、作品の終端でのみ下げます。

これはAIが制作時に適用するルールです。新作作成ツールやパイプラインが自動挿入する機能ではありません。
`story\narration.json` にタイトル／エンディングのシーンを置き、`src\scenes.js` に対応する演出を実装します。
ナレーションが不要なら `lines: []` と `hold` で尺を指定できます。
既存作品に遡って追加することはせず、改修対象として依頼された場合に対応します。

## 台本から時刻を決める

`story\narration.json` を時刻の元データにします。生成した `build\timeline.json`／`timeline.js` は手編集しません。

```json
{
  "voice": "ja-JP-NaokiNeural",
  "rate": "-4%",
  "gap": 0.5,
  "scenes": [
    {
      "id": "s0",
      "title": "紹介",
      "theme": "light",
      "lead": 1,
      "tail": 1.5,
      "lines": [
        {
          "id": "s0a",
          "text": "オフィスキャストへ、ようこそ。",
          "caption": "Office Castへ、ようこそ。"
        }
      ]
    },
    {
      "id": "s1",
      "title": "間",
      "theme": "dark",
      "hold": 2,
      "music": "none",
      "lines": []
    }
  ],
  "markers": {
    "show": {"line": "s0a", "edge": "start", "offset": 0.3},
    "endCard": {"duration": true, "offset": -1.5}
  }
}
```

シーンIDと行IDは、それぞれ台本内で重複不可です。

| 項目 | 意味 |
|---|---|
| `lead`／`tail` | ナレーションの前後の余白秒数。省略時は各1秒 |
| `gap` | 同じシーン内の行間秒数。省略時は0.5秒 |
| 行の `pre` | 2行目以降で `gap` を上書き。1行目の余白は `lead` で指定 |
| `hold` | `lines: []` のシーンの長さ。0.1～600秒。無音声シーンでは `lead`／`tail` は使わない |
| `caption` | 表示用の文。省略すると `text`。音声の読みと英字表記を分けられる |
| 行の `rate` | その行だけ読み上げ速度を上書き |
| `theme` | `light` または `dark`。背景と字幕色を同期 |
| `music` | 同じ曲の楽器編成を切り替える。テンポ・拍・コード進行は引き継ぐ。`none` はBGMなし |

`lines: []` はナレーションなしを意味し、BGM／効果音は別指定です。
作品全体の最終ミックスまで完全無音にするケースは現在サポートしておらず、エラーになります。
終端は30fpsのフレーム数に合わせて切り上げます。字幕は各音声行の開始から終了まで表示します。
画面の左右96px、上下54pxを基本安全域とし、長文は短い行に分割して実際の画面で確認します。

`markers` は数値秒の絶対時刻、または上のような相対指定です。
基準は `scene`、`line`、`duration` のいずれか1つで、`edge` は `start`／`end`、`offset` は秒数です。
読み上げの長さが変わっても、行・シーンに相対的な演出は追従できます。

### 読み方を補正する

行に `ssml` を追加できます。本文の文字列は `text` と一致させ、読みだけを `sub`／`phoneme` などで変えます。

```json
{
  "id": "s0a",
  "text": "Office Castへ、ようこそ。",
  "ssml": "<sub alias=\"オフィスキャスト\">Office Cast</sub>へ、ようこそ。"
}
```

音声・速度・本文・SSML・WAVハッシュが一致する行は再合成しません。
字幕や余白の変更だけなら既存の音声を使って `build --offline` できます。
声を変える、読みを直す、WAVを変更する場合はオンラインビルドが必要です。
全行を録り直すときは `build --force-voice` を使います。`--offline` と併用不可です。

## 演出を書く

`src\scenes.js` に台本の各シーンを登録します。時刻は作品全体の秒数です。

```javascript
OfficeCast.scene('s0', (K, layer) => {
  const scene = K.S('s0');
  const line = K.L('s0a');
  const title = K.div(layer, 'heading', 'Office Cast', { left: 120, top: 140 });
  const tanaka = K.person('tanaka', 760, layer, { width: 300 });
  const robot = K.robot('blue', 1240, layer, { width: 280 });
  K.pop(title, scene.start + 0.1);
  K.pop(tanaka.el, scene.start + 0.3);
  K.pop(robot.el, scene.start + 0.5);
  tanaka.idle(K.tl, scene.start, scene.end).wave(K.tl, line.start, { s: 'L', times: 1 });
  robot.idle(K.tl, scene.start, scene.end);
  const memo = Props.hand('memo', tanaka, 'R', { text: '新しい物語', title: '台本' });
  memo.pose(K.tl, line.start, 'present');
  K.cue(scene.start + 0.5, 'pon', 0.4);
});
```

| API | 用途 |
|---|---|
| `K.S(id)`／`K.L(id)` | シーン／行の `start`・`end` を取得。不明なIDはエラー |
| `K.M.name` | 台本で定義したマーカー |
| `K.div(parent, className, text, css)` | 絶対配置した文字／箱。数値位置はpx |
| `K.person(key, x, parent, opts)` | 会社員プリセットを配置 |
| `K.robot(color, x, parent, opts)` | 色別のロボットを配置 |
| `K.prop(name, opts, x, y, parent)` | 小物を配置 |
| `K.pop(el, time, delay)` | 共通の登場アニメーション |
| `K.tl` | 共有GSAPタイムライン。アニメーションをここへ追加 |
| `K.cue(time, name, gain)` | 効果音キュー。既知の名前、範囲内の時刻、gain 0～4が必要 |
| `K.preload` | 起動前にdecodeする画像URLの配列 |
| `K.post` | seek後に呼ぶ更新関数の配列。Promiseを返してよい |
| `K.sequence(img, frameAt)` | 連番画像を選択し、`img.decode()` 完了までseekを待機 |

座標は1920×1080です。会社員／ロボットの `x` は足元中心、標準地面は `K.GROUND = 930`。
`opts.ground` で足元の高さを変えられます。小物の原点は種類によって異なるため、素材一覧を参照してください。

`K.sequence` の `frameAt(t)` は画像URLか `null` を返します。`null` は更新しないという意味で、画像を非表示にはしません。
作品固有の画像は例えば `src\assets\frames` に置き、URLはHTMLを基準に指定します。
画像欠落やdecode失敗はレンダーを停止します。
動画クリップの自動フレーム抽出、外部クリップ音声の合成、単語単位の時刻生成は今回の共通パイプラインには含めていません。

`tests\fixtures\motion.js` は、ロゴを透過PNGとして `K.preload` で読み込む技術例です。
透過処理、原画・生成元と加工条件の保存、画像ごとに異なる分割位置と縦横比については
[素材ガイド](ASSETS.md#shu-worksのロゴとエンディング)を参照してください。
PNG形式でも背景が透明とは限らないため、アルファと暗い背景上での輪郭を確認します。

各シーンの構築時に要素をつくり、GSAPタイムラインに動きを登録します。
`setTimeout`、実時刻、毎回異なる乱数、再生コールバック内のDOM追加は避けます。
任意の時刻への前後seekで同じ絵になるようにします。
台本にないシーンを登録しても自動で動画に追加されません。台本にある未実装シーンはエラーです。

### 動きを増やすときの基準

登場アニメーションだけで終わらせず、台詞や場面の意味に合った身振り・視線・反応を入れます。
全員を常時大きく動かすのではなく、主役から順に動かして視線を誘導します。
手振り、うなずき、軽い跳ね、メモの提示、画面の描画などを、既存のリグ／小物APIで組み合わせます。
ナレーターの声で全員が話しているように見せる口パクは、自動では追加しません。

冒頭の挨拶とロボットの反応、会社員それぞれのポーズ、
小物の動き、お辞儀などを内容に合わせて組み合わせます。
同じ部位に重なる動きを詰め込みすぎず、動きの開始から終了までを場面の尺内に収めます。
例えば `idle` の呼吸と `bow` は両方とも胴体の `scaleY` を操作するため、
お辞儀の前に呼吸の区間を終了させます。重ねると通常再生と逆seekで異なる姿勢になる場合があります。
小物や腕が隣のキャラ・字幕へ重ならないか、ジャンプの頂点や手振りの最大位置も確認してください。
レンダーでは各シーンの25%・50%・75%地点で往復seekを確認します。
短い動作はこれらの地点から外れることがあるため、動作中の時刻を別途確認します。

## 音楽とミックス

作品の `project.json` で次のプリセットを選べます。

| プリセット | 内容 |
|---|---|
| `office-main` | 既存共通テーマのマリンバ、ピチカート、ウッドブロック、グロッケン、シェイカー |
| `office-light` | 同テーマの少ない楽器による軽い編成 |
| `calm-piano` | ピアノとパッドによる落ち着いた編成 |

**BGMは映像のシーンとは独立した、作品全体で一続きの曲として生成します。**
音符／コードは共通素材ですが、完成WAVは作品の全体尺に合わせて新規生成します。
作品のプリセットが固定BPMとメロディー／コードの開始位置を決めます。
各シーンに拍数を押し込んでテンポを変えたり、メロディーやコードを先頭へ戻したりしません。

シーンの `music` 指定は、曲の変更ではなく**同じ曲の楽器編成の変更**です。
例えば `office-light` → `office-main` でもマリンバ・ベース等の共通楽器は演奏と余韻を継続し、
追加／削除する楽器だけを境界前後の約0.6秒で滑らかに切り替えます。
シーンで `calm-piano` を指定する場合も、作品側の拍・コード進行を引き継ぎ、ピアノ／パッドへ編成を変えます。
そのプリセット独自の開始位置／BPMを使いたい場合は、作品の `project.json` 側で選んでください。

フェードは原則として作品の冒頭と末尾のみです。末尾は1.2秒で下げます。
`music: "none"` で明示した区間は例外で、直前の最大0.6秒で音を下げ、
指定区間のBGMは完全に無音にし、再開時は最大0.6秒で上げます。
再開後も曲の時計は進んでおり、曲を先頭からやり直しません。
異なる曲への切り替えや拍単位の編集機能は未実装です。映像の区切りだけを理由に曲を変更しないでください。

効果音seedを変えるとノイズ系の音色が変わります。同名・同seedの効果音は呼び出し順に依存しません。

ミキサーはナレーション中のBGM／効果音を滑らかに下げ、行ごとの声／BGM比を16dB以上に確保します。
WAVは-2dBTPにリミットし、AAC化後の完成MP4で-16 LUFS付近、-1.5dBTP以下を確認します。
標準ゲインはツール内で共通化しています。作品固有の効果音の大きさはまず `K.cue` のgainで調整してください。

### 1.0.0で起きた問題と再発防止

初版では、新規BGM生成器を「各シーン内で曲を作り直して連結」する方式にしてしまいました。
これは元の依頼や既存プロンプトの指定ではなく、共通化時の実装判断です。
結果として拍・コード・テンポが毎回リセットされ、音の余韻が切れ、
境界の60ミリ秒フェードによって音が一度沈む、ぶつ切りの聴こえ方になりました。
音量／True Peak等の品質確認だけでは、音楽的な不自然さを見つけられませんでした。

1.1.0では全編共通の音楽時計へ変更しました。次を制作・変更時の基準にします。

1. 同じ編成のまま映像シーンを追加／分割しても、生成BGMの全サンプルが変わらないこと。
2. 編成変更後も共通楽器の音、拍、コードを継続し、境界で全体音量をゼロへ落とさないこと。
3. BGMの停止は `none` の明示時だけとし、再開後も元の曲の位置へ戻ること。
4. シーン境界の前後を含むBGM単独と最終MP4を試聴し、リズムの再スタート、余韻の切断、不要な音量の谷がないこと。

1～3は音声の回帰テストに含めています。音量の数値合格と、試聴による自然さの確認は別項目です。
`audio\bgm_info.json` に全編共通時計、BPM、編成切り替え／末尾フェード秒数を記録します。

## 部分実行

通常は `build` を使ってください。工程ごとの調査時には以下の順で実行できます。

```powershell
.\.venv\Scripts\python.exe .\tools\pipeline.py tts --production my-next-video
.\.venv\Scripts\python.exe .\tools\pipeline.py timeline --production my-next-video
npm run render -- --production my-next-video --cues
.\.venv\Scripts\python.exe .\tools\pipeline.py audio --production my-next-video
.\.venv\Scripts\python.exe .\tools\pipeline.py mix --production my-next-video
npm run render -- --production my-next-video --video
.\.venv\Scripts\python.exe .\tools\pipeline.py mux --production my-next-video
.\.venv\Scripts\python.exe .\tools\pipeline.py qc --production my-next-video
```

台本／作品設定／共通設定が変わったのに古いtimelineを使う操作は拒否します。
演出やキュー変更後に一部工程だけ実行すると、別工程の中間物は更新されません。
成果物を確定するときは全ビルドを行い、依存工程の実行漏れを避けてください。

任意時刻の確認用JPEGは次のように生成します。

```powershell
npm run render -- --production my-next-video --stills "1,2"
```

`out\stills\t*.jpg` に保存します。時刻は作品の範囲内で指定します。
`--video` ではシーン中間の静止画とポスターも生成し、`qc` は一覧画像を生成します。
1.4.1から一覧画像は台本のシーンIDを順番に参照します。IDの `s` 接頭辞は不要で、
古いシーンや追加の時刻指定静止画は混ぜません。必要なシーン静止画が欠けていればエラーになります。
`qc` は完成MP4の最終フレームを `out\ending.png` として保存します。
レンダーは標準4並列。負荷を下げる場合は `--workers 1` を指定できます。
ブラウザの変更は `OFFICE_CAST_BROWSER`、FFmpegの変更は `FFMPEG` で指定できますが、変更後は再確認が必要です。
